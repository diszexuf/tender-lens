# Tender Lens

Система обоснования начальной (максимальной) цены договора (НМЦК) методом сопоставимых рыночных цен: по описанию закупки ищет сопоставимые предложения в открытых источниках, оценивает их сопоставимость, исключает аномалии и формирует проверяемый отчёт.

> Статус: этапы 1–3 плана, кроме ГИСП и КТРУ ([план](docs/04-implementation-plan.md)).

## Что умеет

- Разбирает текст закупки в спецификацию: позиции, количество, единицы ОКЕИ, типизированные характеристики (число, диапазон, перечисление, да/нет). Спецификацию можно проверить и поправить до поиска и после расчёта.
- Собирает предложения: реестр контрактов ЕИС, сайты магазинов (`html`-источники с селекторами или без), веб-поиск через SearXNG. Источники добавляются и проверяются из UI без правки кода.
- Оценивает сопоставимость: дубли и одна цена на поставщика, top-K по текстовому сходству, характеристики сравнивает код (LLM только извлекает значения и проверяется по тексту), релевантность с порогом.
- Нормализует цены: единицы и фасовка, НДС, индексация по ИПЦ, возраст цены, регион.
- Считает НМЦК по методике: MAD/IQR-выбросы, CV ≤ 33 %, минимум 3 цены; при неоднородности цену не выдаёт и подсказывает группы цен.
- Отчёт: каждое решение с причиной, шаги нормализации, ссылки на сохранённые копии страниц-источников; ручные решения с комментарием; версии расчёта и их сравнение; выгрузка XLSX (с формулами), PDF, HTML и полного следа в JSON.

## Как это работает

```
текст закупки ─► разбор (LLM) ─► спецификация ─► сбор по источникам ─► дедупликация
     ─► top-K ─► характеристики (код + LLM) ─► сравнение кодом ─► нормализация (ед., НДС, ИПЦ)
     ─► ручные решения ─► выбросы, CV, n ─► цена позиции ─► НМЦК + отчёт (версия)
```

Сбор идёт параллельно по парам «позиция × источник»; сбой источника фиксируется и не прерывает расчёт, после серии ошибок источник временно отключается (circuit breaker). Этап оценки работает только с данными в БД, поэтому перерасчёт с другими настройками или ручными решениями не ходит в источники и использует кэш извлечённых характеристик. Подробно — в [архитектуре](docs/03-architecture.md#4-пайплайн-расчёта).

## Примеры (реальные прогоны)

**UC-01. Одна позиция с техническими характеристиками.**

```
Кабель силовой ВВГнг(А)-LS 3х2,5 мм², медный, количество жил 3, сечение жилы 2,5 мм². Количество — 500 м.
```

Результат: 22 предложения; в выборке 4 цены исполненных контрактов ЕИС, CV 17,45 % — «Цена определена»: 114,11 ₽/м, позиция 57 055,00 ₽. Исключены: 10 цен магазинов (контрактов достаточно), 5 — не совпала обязательная характеристика (марка, сечение), 2 — более ранняя цена того же поставщика, 1 — неустойки по контракту.

**UC-02. Несколько позиций в упаковках.**

```
Поставка канцелярских товаров:
1. Бумага офисная А4, 80 г/м², белизна не менее 146% CIE, 500 листов в пачке — 200 пачек.
2. Ручка шариковая синяя, толщина линии 0,7 мм — 500 шт.
3. Скрепки металлические 28 мм, упаковка 100 шт — 100 упаковок.
```

Результат: «Неполный расчёт», НМЦК 66 444,00 ₽ только по бумаге (332,22 ₽ за пачку, n = 4, CV 7,64 %). Ручки (CV 45,2 %) и скрепки (CV 62,8 %) — «Неоднородная выборка», цена не сформирована; для скрепок система показала две группы цен (18–32 ₽ и 69–70 ₽) и предложила уточнить характеристики или исключить предложения вручную.

Цены зависят от того, что источники отдают в момент расчёта, поэтому повторный прогон даёт близкие, но не те же числа.

## Работа с расчётом

| Действие | Где |
|---|---|
| Проверить спецификацию до поиска | «Новый расчёт» → «Проверить спецификацию перед поиском» |
| Исключить или включить предложение | Отчёт → позиция → строка предложения → «Исключить вручную» (с комментарием) |
| Изменить характеристики или количество после расчёта | «Изменить спецификацию» → перерасчёт; новая позиция или новый запрос — сбор только по ним |
| Сравнить версии | Выбор версии → «Сравнить версии» |
| Выгрузить отчёт | «Выгрузить» → XLSX (формулы по строкам выборки), PDF, HTML, полный след JSON |
| Пороги, правило выбросов, НДС, индексация | «Настройки» → «Правила расчёта» (каждое сохранение — новая версия настроек) |
| Единицы, синонимы, ИПЦ | «Настройки» → вкладки справочников |
| Состояние источников | «Источники» → колонка «Состояние»; «Сбросить ошибки» снова включает источник |

## Требования к окружению

| Компонент | Версия / объём |
|---|---|
| Docker Engine + Compose | Docker 27+, Compose v2.24+ |
| GPU (рекомендуется) | NVIDIA с 6 ГБ VRAM и драйвером с поддержкой CUDA; на Windows — Docker Desktop с WSL2 |
| RAM / диск | 16 ГБ / 20 ГБ свободного места (образы ~3 ГБ, модель ~2,5 ГБ) |
| Python | 3.14 — только для генерации `.env` и локальной разработки |

## Быстрый старт

```bash
# 1. Создать .env со случайными секретами (или скопировать .env.example и заполнить вручную)
python infra/init/gen_env.py

# 2. Собрать и запустить всё
docker compose up -d --build

# 3. Открыть
#    UI:       http://localhost:8080   (раздел «Состояние» — готовность сервисов)
#    Swagger:  http://localhost:8000/api/docs
```

Первый запуск скачивает образы и модель LLM (`OLLAMA_MODEL`), это занимает несколько минут. Пока модель загружается, компонент `llm` на странице состояния имеет статус «Частично».

**Без GPU:**

```bash
docker compose -f docker-compose.yml -f docker-compose.cpu.yml up -d --build
```

Оверрайд убирает у `ollama` требование видеокарты. Передавайте оба `-f` во всех командах (`logs`, `down`, `restart`). На CPU вызов модели в несколько раз медленнее: расчёт позиции занимает минуты. Если в логах воркера появляется `LLMError … timeout`, уменьшите «Размер пачки LLM» в «Настройках» до 2.

**Остановка:**

```bash
docker compose down        # остановить, данные сохраняются в томах
docker compose down -v     # остановить и удалить все данные (БД, хранилище, модели)
```

## Сервисы

| Сервис | Назначение | Порт на хосте |
|---|---|---|
| `web` | Vue 3 + Vuetify SPA, nginx (проксирует `/api`) | `WEB_PORT` (8080) |
| `api` | FastAPI | `API_PORT` (8000) |
| `worker` | Taskiq-воркер пайплайна (с Chromium) | — |
| `postgres` | PostgreSQL 18 | — |
| `redis` | Valkey: очередь задач, кэш | — |
| `garage` | S3-хранилище снапшотов и отчётов | — |
| `ollama` | Локальная LLM | — |
| `searxng` | Метапоиск | — |
| `init` | Одноразово: миграции БД, настройка Garage (идемпотентно) | — |
| `ollama-pull` | Одноразово: загрузка модели LLM | — |

Внешние сервисы: только открытые источники данных (ЕИС, ГИСП, сайты поставщиков) и поисковые системы через SearXNG. Внешние LLM API не используются.

Полный список с комментариями — в [.env.example](.env.example). Основные:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `WEB_PORT`, `API_PORT` | 8080, 8000 | Порты на хосте |
| `POSTGRES_*` | — | Подключение к БД |

| `OLLAMA_MODEL` | `qwen3:4b` | Модель LLM; `qwen2.5:7b` точнее, но на 6 ГБ VRAM частично уходит на CPU |

| `SEARXNG_SECRET` | — | Секрет SearXNG |
| `EIS_TOKEN` | пусто | Токен сервиса данных ЕИС (необязательно) |

## Проверка системы

Системные тесты проверяют развёрнутую систему как чёрный ящик — только по HTTP через nginx, без доступа к коду: готовность всех сервисов, соответствие API контракту `contracts/openapi.json`, работу SPA и прокси.

```bash
# В контейнере, внутри сети Compose (стек должен быть запущен)
docker compose --profile test run --rm --build system-tests

# Или локально против http://localhost:8080
cd tests/system
python -m venv .venv && .venv/Scripts/pip install uv && .venv/Scripts/uv sync
.venv/Scripts/pytest -v
```

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TL_BASE_URL` | `http://localhost:8080` (в контейнере — `http://web`) | Адрес системы |
| `TL_ALLOW_DEGRADED` | пусто | Компоненты, которым разрешено «Частично», например `llm`, пока скачивается модель |
| `TL_READY_TIMEOUT` | 120 | Сколько секунд ждать готовности системы |

```bash

cd backend
python -m venv .venv && .venv/Scripts/pip install uv   # Linux/macOS: .venv/bin/pip
```

## Версии образов

Все образы закреплены как `тег@digest` (в `docker-compose.yml` и Dockerfile) — сборка воспроизводима. Чтобы обновить образ, найдите новый тег и его digest:

```bash
docker buildx imagetools inspect postgres:18.8-alpine --format '{{json .Manifest.Digest}}'
```

## Если не запускается

| Симптом | Что проверить |
|---|---|
| `ollama` не стартует, ошибка про `nvidia` | Нет GPU или NVIDIA Container Toolkit — запустите с `docker-compose.cpu.yml` |
| `init` завершился с ошибкой | `docker compose logs init`; часто — неверные `GARAGE_*`/`S3_*` в `.env`. Формат ключа: `GK` + 24 hex, секрет — 64 hex |
| В «Состоянии» `llm` — «модель не загружена» | Модель ещё скачивается: `docker compose logs -f ollama-pull` |
| `worker` — «нет сигнала от воркера» | `docker compose logs worker` |
| UI открывается, но API отвечает 502 | `docker compose ps api` — API ещё стартует или упал |
| Выгрузка PDF отвечает 503 | PDF рисует воркер (Chromium): `docker compose logs worker`; XLSX и HTML формирует API и работают без воркера |
| Источник в отчёте «Временно отключён» | Сработал circuit breaker после ошибок подряд; «Источники» → «Сбросить ошибки» |
| Цена ЕИС не индексируется | В «Настройках» → «Индексы цен» нет месяцев после даты контракта — добавьте ИПЦ Росстата |
